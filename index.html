    1.拖地时候可以水里放点护发素

    平常在家里拖地的时候，可以适当使用一些清洁剂，但是大部分的清洁剂只是有去污的效果，地面是清洁干净了，但是时间久了，瓷砖地板会乌秃秃的，教你一个小方法，能瞬间让地面光亮。

    拖地的时候可以在水中加入一点护发素，它能使瓷砖或者木质地板的表面清洁过后更加光亮，而且几天不拖地也少有灰尘。

    随笔的意义

    有的人渴望发布一些东西，有些人一定要发布一些东西。

    余杰在他的《心灵独白》中第一句话便说：“世界上最不能容忍的垃圾——文字垃圾。所以我每次提起笔时，不禁心凉胆战。”事实上我在动手写博客里这些文章的时候，无不抱有这种心情。

    很开心，自己也一直能够秉持这么一股信念，就算不发文章，也绝不直接在网上复制粘贴或者转载一些并不好用的文章到自己的博客里来。可能我们每个人都有过被网上那些复制粘贴的文章误导或者伤害的经历，每念及此，我就宁肯不发文章，也不愿意像那样弄一些无关痛痒的文章来。

    很多时候，我们在工作生活中，浏览着大量的内容，也许就在这些浏览当中蹉跎了时光，消磨了学习的精神头。

    每个人体内都住着一个毒液

    前年看《毒液》，我给的评价七分，理由是"毒液和埃迪的兄弟情是全片的灵魂"。当时写这句话图的是好玩——一个怂记者和一个狂外星人的互怼，喜剧效果拉满。最近重翻这篇影评，忽然觉得它更像一份中年人的体检报告。

    埃迪·布洛克，事业砸了，女友散了，捡了个寄生生物回家。从此身体里住进另一个自己：半夜三点想吃巧克力和鸡脑子，受了委屈直接喊出来，看谁不爽就说要吞了他。毒液说的每句话，都是埃迪不敢说的那半句。电影把这套设定拍成了笑料，可你要是仔细听，那其实是一个人内心生活的实况转播：理性在踩刹车，欲望在踩油门，两边全天吵架，方向盘只有一个。

    年轻的时候我以为成熟就是杀死毒液。把脾气磨掉，把馋戒掉，把那些不合时宜的真话咽回去，做一个情绪稳定的社会人。后来发现这条路不通——毒液是杀不死的，你越压，他叫得越响，最后不叫了，人也没劲了。所谓"情绪稳定的成年人"，练到后面我算是明白了，不是把体内那个狂家伙干掉，而是跟他谈成了一纸合约：你饿了给你好吃的，你想说话找个安全的场合说，方向盘归我，副驾归你。

    崩溃符号化体系搭建：dSYM 的收集、匹配与找回

    崩溃平台的原始堆栈长这样：MyApp 0x0000000104a2c8f0 0x102a1c000 + 33753328。符号化做好之前，它约等于"App 死了，死因不详"。符号化体系是崩溃监控的地基，很多团队的监控"不准"，问题不在采集端，在这条 dSYM 流水线上。这篇把我们趟出来的完整方案记下来。

    符号化的原理：三件套对得上才行

    崩溃栈的还原需要三个东西精确咬合：

    崩溃日志:  帧地址 0x104a2c8f0  +  二进制加载基址 0x102a1c000
            └─ 偏移量 = 33753328 (日志已替我们算好)
dSYM:      偏移量 → 函数名/文件/行号 的映射表
UUID:      日志里二进制的 UUID 必须与 dSYM 的 UUID 完全一致

    体重秤上的复利

    《增肌增重计划》开头那句话，我想了很久要怎么评价："我一直偏瘦，穿衣服总感觉撑不起来。几年前就想过增肌，但一直没认真执行。"

    "想"和"认真执行"之间隔着的几年，大概是所有成年人的通病。增肌这件事的难点根本不在健身房，在饭桌上：一天要吃到两千大卡出头，蛋白质按体重称着克数吃，练完哪怕不饿也要把那份加餐塞下去。对一个天生吃不香的人来说，多吃不是享受，是任务。

    但计划里最好看的是那六个字："体重稳步在涨"。没有奇迹，没有一个月二十斤的爽文，就是数字每周往上爬一点点。我特别理解这种爬行带来的快乐——写代码的人都懂，一个红色测试用例慢慢变绿有多爽，体重秤就是你的测试用例，吃进去的每一口都是提交，身体这个老程序员每周给你跑一次构建，结果不撒谎。

    让 AI 写单元测试：一套能落地的工程流程

    "用 AI 写测试"这个话题的教程很多，但多数停在"把代码丢给模型，它吐出一个测试文件"。真在项目里跑起来，会撞上一堵墙：生成的测试一半编译不过，另一半断言的是"代码现在是什么就断言什么"——这种测试只能锁死现状，防不了 bug。三个月实践下来，我摸索出一套流程，把 AI 从"代码生成器"调教成了"测试实习生"，记录一下。

    为什么裸写 Prompt 效果差

    直接 帮我给这个类写单元测试，会得到三种典型废品：

    1. 翻译式测试：把被测代码逐行翻译成断言，add(1,2) 断言 == 3 不是因为"规格说应该得 3"，而是因为"实现返回了 3"。实现改错，测试跟着改错。
    2. 幻觉 API：调用类里根本不存在的方法，或者拿 Swift 的 API 去测 OC 类。
    3. 依赖真空：真实初始化被测对象，网络、数据库全被拉起来，测试变成集成测试，一跑三分钟。

    十天的花期

    《洛阳牡丹花会三天旅游攻略》里有一行小字，是整篇里我唯一反复核对过的信息：牡丹的盛花期，约十到十五天。攻略的其他部分都可以事后补，只有这一条不行——花不等人，去晚了，满城富贵就只剩满城绿叶。

    十到十五天，是洛阳给自己定的年度期限。每年四月初，全城开始倒计时：花期预报精确到品种和园区，高铁票、酒店、牡丹饼的产能，全部围绕这两周排兵布阵。一座城市为一个花期动员成这样，看起来夸张，可你想想，哪一件美好的事不是这样呢——潮水有汛期，果子有成熟期，好运气有好窗口。它们共同的脾气是：来时有日子，过时不候。

    人到了会看日历的年纪，才看得懂花期的残忍和慈悲。残忍是明说：你只有这几天。慈悲也是明说：就是这几天，所以值得你请假、值得你挤、值得你把闹钟定在六点去赶早开的头一茬。反倒是那些"随时可以去看"的东西，我们总留着留着就再也没去过。"改天"是世界上最宽的懒床，躺着最多的没成行的计划。

    iOS 深色模式适配踩坑录：那些颜色反了的地方

    深色模式上线一周年，复盘一下这条路。当年觉得"系统自动反色，白捡的功能"，实际做完花了两个迭代，一半的坑不在颜色本身，在那些"系统够不着"的角落。

    地基：Color Assets 不是可选项

    硬编码颜色在深色模式下就是灾难。全部收敛到 Asset Catalog 的 Color Set，一个颜色两个外观，代码里只用语义名：

    // ❌ 深色模式下白底白字就是这么来的
label.textColor = [UIColor whiteColor];

// ✅ 语义化命名：关心"是什么"，不是"什么色值"
label.textColor = [UIColor labelColor];                    // 系统语义色
view.backgroundColor = [UIColor colorWithName:@"bg_card"]; // 自建语义色
